# 歌曲页维护

- `songs.js`：歌曲清单，原顺序继续表示添加顺序。
- `playlist.js`：虚拟列表、搜索、排序、按需音频及首字母定位。
- `index.html`：页面结构与原有样式。
- `alphabet.css`：微信式 A–Z、# 竖向索引和大字母提示的样式。

首字母以歌名为准；中文复用浏览器的拼音排序规则，英文取首字母，数字及其他字符归入 #。全部27个入口都显示，没有对应歌曲的字母置灰不可选。

选择字母会切换到拼音分组排序，并跳到该组第一首；点击或上下拖动都不加载音频。选中字母是绿色圆形，拖动时显示大字母提示，松开后短暂保留。键盘也可定位。添加时间排序继续保留原始添加顺序。

桌面使用右侧窄歌单，索引位于歌单右边；1000px及以下贴页面左侧，字母与提示都缩小，列表留出索引空间。手机列表保留正常排版以避免滚动时重建卡片；桌面仍使用虚拟列表。播放器只在点击播放后创建，不预载整张歌单。

新增歌曲只需更新 `songs.js`，字母分组随清单自动更新；不用维护另一份索引或引入拼音字典。

更新歌单、样式或播放代码后运行 `npm run build:songs`，再运行 `npm run check:songs` 验证发布入口。不要直接修改生成的 `playlist.bundle.js` 或 `index.html` 中 `songs:styles` 标记之间的样式。

手机索引由独立的原生触摸事件处理，统一使用视口 clientY 定位同一根手指，不混合 screenY/pageY 差值；每帧仅执行最后一次字母定位，忽略重复 Pointer 事件及无效坐标，抬手时提交最后落点。修改此逻辑时，应测试快速往返、触摸取消、普通页面滚动及播放互斥。

手机歌曲内容在 `#playlist-viewport` 内滚动，搜索栏与字母索引位于它外侧；不要把字母跳转改回 `window.scrollTo`。修改后应验证小幅移动与边界抖动不会跳到 A/#，同时确认列表能正常手动滚动及搜索、排序、播放。

## 电脑版黑胶播放器

宽度超过 1000px 时，左侧为黑胶唱片和唱臂，中间为扇形歌词，右侧为虚拟歌单与搜索。点歌后，独立的当前播放卡片显示在页面顶部并保留暂停/继续按钮；右侧所有歌曲保留原有位置、排序和滚动位置，当前歌曲也留在原位，不修改 `songs.js` 的添加顺序。

- `vinyl-player.html`：用户提供的 `hi_fi_vinyl_radial_lyrics_player-3.html` 的网站适配副本，保留 Three.js、jsmediatags 及其许可、唱臂状态机和歌词解析器。取消演示曲启动、外部字体和本机辅助服务探测。
- `vinyl-bridge.js`：将当前歌曲文件接入原播放器，读取内嵌封面/歌词。歌曲切换会取消旧请求、撤销旧音频资源；上一首/下一首按当前歌单排序选择歌曲。
- `vinyl-desktop.js`：首次点歌才加载播放器页面；整个歌单共用一个播放器和一个音频元素，不为未选歌曲下载音频。通过隔离页面保留原播放器的样式与滚轮歌词操作。首次点击同步唤醒 AudioContext，并以本地静音 WAV 授权同一个音频元素，再将其交给播放器，兼容 WebKit 的播放授权；不请求未选歌曲。
- `vinyl-desktop.css`：仅电脑版布局，深色与暖金配色。1000px 及以下仍使用原生音频控件；跨过此断点会停止当前播放并卸载桌面播放器，避免隐藏音频继续播放。

网站歌词从构建时提取的小型资料文件读取内嵌时间轴，再请求 LRCLIB；手动导入实际音频的独立播放器仍支持内容缓存。网络匹配保留歌曲、歌手、版本和时长校验（允许整数秒时长舍入及 MP3 填充误差），不把网络时间轴称为已核验音频。现场版与录音棚版不能互换。无可用歌词时显示提示，可在“歌词总览”中补充 LRC；无时间轴的文本不伪造同步。歌词同步检查应区分实际在线可用性和受控测试时间轴。

`scripts/build-favorsongs.mjs` 按依赖顺序更新 SHA-256 前 12 位查询指纹：`vinyl-bridge.js` → `vinyl-player.html` → `vinyl-desktop.js` → `playlist.js` → `playlist.bundle.js` → `index.html`，避免浏览器混用版本。

跨设备播放默认使用 80 kbps AAC-LC 流畅副本，M4A 索引提前放在文件头（faststart），无内嵌大封面。音质选择可切回原始 MP3，并保存在浏览器本地。首次点歌立即缓冲音频，与播放器下载并行；播放器接管同一个音频元素时保留已缓存的数据。封面和歌词只取几百字节的 JSON 与约 192 像素缩略图，不再额外下载整首歌曲。封面等缓冲超过 15 秒再请求。连续 30 秒无法继续播放会停止并提示重试，用户暂停不计超时；三维画面初始化失败或低于约 2 FPS 持续阻塞启动时自动使用兼容画面。

首屏只请求页面和一个 `playlist.bundle.js`（含歌单数据和列表逻辑），两份小样式在构建时内联；入口脚本在 head 中 modulepreload，去掉串行歌曲清单请求。使用内容指纹而非每次打开的随机时间戳，清单变化会生成新地址。初次打开不下载播放器、Three.js、音频或封面。`_headers` 为带指纹的入口设置一天缓存，并要求歌曲页 HTML 重新验证。三秒目标以歌单和搜索/字母索引可操作为准，仍取决于实际网络和服务器响应。

## 流畅音频与资料构建

- `streams/*.m4a`：生成的 80 kbps AAC-LC 副本，原始 MP3 完整保留。
- `details/*.json`、`details/*.jpg`：版本信息、歌曲/歌手/专辑、内嵌歌词、封面缩略图；现场版和录音棚版按各自文件区分。
- 新增或替换音频后运行 `npm run build:song-media`（需要 ffmpeg，或设置 `FFMPEG` 环境变量）。脚本根据原文件 SHA-256 跳过未变化音频，随后提取内嵌歌词并更新入口。
- 只改页面代码时运行 `npm run build:songs` / `npm run check:songs`。构建会核验每首歌的副本、资料和封面，并生成统一内容版本，避免浏览器缓存旧音频资料。
- 发布时须同时上传 `streams/` 和 `details/`，不能只更新页面脚本。没有发布这些文件的旧站点不会获得流畅音质。
